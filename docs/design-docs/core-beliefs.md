# 核心信念（智能体优先的操作原则）

1. 人类掌舵，智能体执行。人类不直接贡献代码行。
2. 工程师的工作是设计环境、明确意图、构建反馈回路。
3. 上下文是稀缺资源；给地图，不给说明书。
4. 智能体在运行时看不到的东西，对它来说不存在。
5. 强制不变量，不微观管理实现。
6. 中央强制边界，本地允许自主表达。
7. 纠错成本低，等待成本高。
8. 技术债是高息贷款，小额高频偿还。
9. 遇到卡点先问："缺的是什么能力？如何让它既清晰可读又可强制执行？"
10. 人类品味要持续被捕捉——写进文档，或直接编码进工具。
11. 交互式决策必须落盘：确认过但不写进仓库的决策等于没做。

## 技术栈结论

用户于 2026-10-12 通过交互确认（需求见 `docs/requirements.md`）。

| 项 | 结论 | 来源 |
|---|---|---|
| 目标平台形态 | iOS 客户端 + Web 管理端 + 服务端（Agent 与数据） | 需求：手机端（iOS）+ Web 管理端；服务端由"模型密钥不能下发客户端、多人共享数据"推出，用户选定方案时一并确认 |
| 语言 | iOS：Swift；服务端与 Web 管理端：TypeScript | 用户选择「SwiftUI 原生 + TS 后端」 |
| 框架 | iOS：SwiftUI；服务端：Hono + Drizzle ORM；Web 管理端：React + Vite | 用户逐项确认 |
| 数据库 | PostgreSQL + pgvector（菜谱语义检索） | 用户确认 |
| 包管理器 | TS：pnpm workspace；iOS：Swift Package Manager | 用户确认 |
| 构建方式 | TS：tsc / Vite；iOS：XcodeGen 生成工程（`.xcodeproj` 不入库）+ xcodebuild | 用户确认 |

### 首版设计决定（2026-10-12 用户确认）

| 项 | 结论 | 来源 |
|---|---|---|
| 大模型接入 | 用户提供的中转站 API，暂定模型 `gpt-6.1-sol`；服务端只实现 OpenAI 兼容接口，供应商在管理端配置 | 用户回答 |
| 菜谱来源 | 自建菜谱库为主（种子来自 HowToCook，Unlicense），模型生成为补充，审核后入公共库 | 用户选择 |
| 账号 | 邀请码 + 设备令牌 | 用户选择 |

详见 `docs/design-docs/recommendation-agent.md` 与 `docs/design-docs/data-model.md`。

### 由结论直接推出的约束

- 服务端通过 OpenAPI 描述接口，Swift 客户端代码由 OpenAPI 生成，保证两种语言的接口一致。
- 大模型密钥只存在于服务端，iOS 与 Web 管理端都不直接调用模型。
