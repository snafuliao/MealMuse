# 一键购买调研：把菜谱食材加入生鲜平台购物车

- **状态**：草稿（调研结论，未评审）
- **调研日期**：2026-10-12（下文「查证」均指这一天；未单独标注日期的结论同此）
- **范围**：盒马、叮咚买菜、美团小象超市、朴朴超市；顺带记录阿里 / 美团 / 京东 / 微信的 AI Agent 购物通道
- **来源需求**：`docs/requirements.md` 首版功能第 4 条

可信度标记：**已证实**＝看到官方文档、官方配置文件或多家媒体一致报道；**部分证实**＝只有单一媒体报道或第三方整理；**未证实**＝没查到，或只有不可靠来源。

## 结论速览

1. **四家平台都没有让第三方 App 往用户购物车里加商品的公开接口**。已公开的开放平台都面向商家或服务商（ISV），做的是门店、商品、订单、履约对接，不是买家侧接口。所以首版做不到真正的「一键加购」。
2. **iOS 上目前能稳定做到的是「生成购物清单＋跳转到平台 App」**。盒马、朴朴已经配置了覆盖全站的 Universal Links（本次实测确认），美团只放行了部分路径。能不能直接打开「搜索结果页」或「商品页」要看 App 内部的路由，这一点需要在真机上验证。
3. **长期最可能出现的路径在阿里生态**。盒马、叮咚、朴朴都已经接入淘宝闪购，淘宝 PC 客户端已经通过 MCP 允许本机 AI 搜索、比价、加购，千问 App 能在对话里下单。但这些能力目前要么只给阿里自家 Agent 用，要么只能在用户自己的电脑上本地运行，还没有向第三方服务端开放。
4. **不做逆向接口或界面自动化**。这样做可能违反平台协议、《反不正当竞争法》第十三条，严重时还可能触犯刑法第 285 条；账号也有被风控封禁的现实风险。

## 2. iOS 端的非接口路径

| 路径 | 能做到哪一步 | 实测或查证结果 | 可信度 | 来源 |
|---|---|---|---|---|
| **Universal Links** | 安装了 App 就直接打开 App；没装就打开网页。无法加购 | 盒马：`www.freshhema.com` 和 `m.hemaos.com` 的 AASA 文件对 `com.wdk.hmxs` 放行全部路径（`*`）。朴朴：`www.pupumall.com` 对 `com.pupumall.customer` 放行 `/*`。美团：`www.meituan.com` 只放行 `/web`、`/c/*`、`/poi/*` 等少数路径。叮咚：没找到 AASA（`100.me` 返回的是网页）。淘宝：本机连不上相关域名，没测到 | 已证实（AASA 文件）；页面级落点未证实 | [S11] |
| **URL Scheme** | 打开 App 首页或指定页面；带参数搜索的格式没有公开文档 | 社区整理的列表里有盒马 `wdkhema://main?index=1`、美团 `imeituan://`；叮咚、朴朴没找到 | 未证实（非官方，可能随版本失效） | [S12] [S13] |
| **从 App 拉起微信小程序** | 打开指定小程序的指定页面 | 要求我们的 App 与目标小程序绑定在同一个微信开放平台账号下，第三方做不到 | 部分证实 | [S14] |
| **iOS 快捷指令** | 由 MealMuse 自己提供 App Intents（例如「获取今天的购物清单」），在快捷指令里组合「复制」「打开 URL」「加入提醒事项」 | 没查到四家平台提供可加购的快捷指令动作 | 未证实（平台侧）；我方能力已证实 | [S15] |
| **清单分享 / 剪贴板** | 把食材清单复制或分享出去，用户在平台 App 里逐项搜索 | 不依赖平台，随时可用 | 已证实 | — |

小结：所有非接口路径**最多只能做到「打开平台并帮用户定位商品」**，加购这一步始终要用户自己点。

## 3. 自动化与逆向接口：风险评估（只评估，不实施）

| 风险 | 说明 | 可信度 | 来源 |
|---|---|---|---|
| 违反平台协议 | 电商平台的用户协议普遍禁止用非官方工具访问；本次没有逐条核对四家平台的协议原文 | 未证实（未逐条核对） | — |
| 《反不正当竞争法》第十三条 | 2025 年修订，2025-10-15 起施行。禁止用欺诈、胁迫、避开或破坏技术管理措施等方式获取、使用其他经营者合法持有的数据 | 已证实（施行日期）；条文据律所解读 | [S16] |
| 刑法第 285 条 | 提供专门用于侵入、非法控制计算机信息系统的程序、工具，情节严重的可以入罪。没查到针对生鲜「抢菜脚本」的判决，但同类外挂已有判例 | 部分证实 | [S17] |
| 账号风控 | 2025-12 豆包手机助手用界面自动化操作微信、淘宝等 App 时，账号被强制下线或触发验证，此后多个平台跟进限制 | 已证实（多家媒体报道） | [S18] |
| 隐私与凭据 | 逆向接口需要保存用户在平台上的登录态（Cookie / Token），这与 `docs/SECURITY.md`「不在服务端保存用户的第三方密码」的要求相冲突（登录态和密码一样敏感）；本项目面向作者和身边的人，泄露的是熟人的账号 | 推论 | — |

结论：**不论是服务端代用户调平台私有接口，还是在设备上做界面自动化，都不做**。

## 4. 推荐方案

### 首版最小可用形态：「采购清单＋跳转」

1. 服务端把每日菜谱的食材汇总成**采购清单**：合并同类项、换算用量、按品类分组，并给每项生成适合在生鲜平台搜索的**关键词**（例如「去皮五花肉 500g」→「五花肉」）。
2. iOS 展示清单，支持勾选「家里已有」，并提供三个动作：
   - **复制清单**、通过系统分享面板发出；
   - **一键写入「提醒事项」**（iOS 自带购物清单），到店或在 App 里购物时逐项勾掉；
   - **打开盒马 / 朴朴 / 美团**：用 Universal Links 打开 App（`UIApplication.open` 配合 `universalLinksOnly` 选项，没装就回退到网页或提示安装），同时把当前这一项的关键词放进剪贴板，用户在 App 里粘贴搜索即可。
3. 用 App Intents 提供「今天要买什么」快捷指令动作，方便用户自己编排自动化。

这一版不需要任何平台授权，也没有合规风险，能马上落地；体验上比「真正一键」多出「粘贴、搜索、加购」三步。

### 长期理想形态：借助平台官方的 Agent 通道

按可能性从高到低：

1. **阿里生态**：盒马、叮咚、朴朴都在淘宝闪购上，淘宝已经有本机 MCP 能加购 [S19]，千问能对话下单，支付宝发布了 ACT 智能体商业协议 [S20] [S21]。一旦淘宝 / 淘宝闪购向第三方 Agent 开放**买家侧**的搜索和加购接口（需用户 OAuth 授权，付款仍由用户确认），MealMuse 服务端就可以把采购清单直接映射成闪购购物车。需要持续关注。
2. **美团生态**：「小美」Agent 只调用美团内部接口，对外开放的报道停留在合作层面（如腾讯元宝）[S22]；收购叮咚后小象超市和叮咚的商品可能合并，值得关注。
3. **微信 AI 生态**：2026-06 起，微信 AI 可以调用小程序完成任务 [S23]。方向是「微信 AI 调平台小程序」，不是「我们调平台」，对 MealMuse 帮助有限；除非将来 MealMuse 自己做小程序。

在这些接口开放之前，不为长期形态写代码，只保持数据结构可以平滑扩展。

### 对架构的影响

- **服务端**：以后新增一个采购清单领域（目录按 `ARCHITECTURE.md` 的约定放在 domains 下），service 层负责食材汇总、用量换算和关键词生成（可以调用模型，输出必须过 zod schema）。清单 schema 放进 `packages/shared`，经 `pnpm openapi` 同步到 iOS。为长期形态预留「平台适配器」接口（输入清单项，输出平台商品候选或加购结果），首版只实现「生成搜索关键词」这一种。**首版不存任何平台账号或凭据。**
- **iOS**：在 `MealMuseKit` 中新增清单的展示和勾选逻辑；在 App 外壳中做 Universal Links 跳转、剪贴板、EventKit（提醒事项）写入和 App Intents。如果需要用 `canOpenURL` 判断 App 是否已安装，要在 `apps/ios/project.yml` 里声明 `LSApplicationQueriesSchemes`（通过 XcodeGen 生成，不手改工程文件）。写入提醒事项需要申请权限，并在 `docs/SECURITY.md` 中说明。
- **管理端**：维护各平台的跳转模板（域名、路径、是否启用），实机验证结果变化时不用发版。
