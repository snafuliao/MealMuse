# 安全要求

- 大模型 API 密钥等机密只存在于服务端：管理端录入的供应商 Key 用 AES-256-GCM 加密存库（主密钥来自环境变量 `MODEL_SECRETS_KEY`），任何接口都不返回明文，只返回末 4 位；`.env` 不入库，只提交 `.env.example`。
- 模型经第三方中转站调用，中转站能看到请求内容：只发送口味档案的结构化摘要与菜谱数据，不发送昵称和账号信息；llm_calls 只记录元数据，不存提示词与回复正文。
- 邀请码与设备令牌只存 SHA-256 哈希；令牌可撤销；邀请码兑换接口要限流。
- iOS 与管理端不内置任何密钥；所有接口都需要设备令牌，管理端接口还要求管理员角色。
- 所有外部输入（HTTP 请求、模型输出、第三方回调）在边界处用 schema 解析，失败即拒绝。
- 用户的口味、饮食记录属于个人数据：只用于推荐，不发送给推荐所需之外的第三方。
- 一键购买若涉及第三方账号，不在服务端保存用户的第三方密码；方案以调研结论为准。
