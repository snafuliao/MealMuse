# 产品规格：Web 管理端

- **状态**：草稿，待用户评审
- **日期**：2026-10-12
- **来源**：`docs/requirements.md`（管理端首版负责模型配置与菜谱管理）

## 1. 登录

- 只有管理员角色能登录。第一个管理员由服务端命令行生成登录令牌（只显示一次），在管理端登录页粘贴即可。
- 登录后令牌保存在浏览器的 HttpOnly Cookie 中，30 天有效，可在管理端撤销。

## 2. 模型配置

- 维护模型供应商，字段：名称、Base URL、API Key、对话模型名（如 `gpt-6.1-sol`）、Embedding 模型名（可空）、超时时间。
- 首版只支持 OpenAI 兼容接口，你提供的中转站就按这种方式接入。
- API Key 只能写入，不能读出：保存后界面只显示末 4 位；修改时需重新输入整串。
- **测试连接**按钮会依次检查：对话能否返回、是否支持结构化输出（JSON Schema）、是否支持工具调用，以及 Embedding 是否可用。结果逐项显示，因为推荐和问答依赖这些能力。
- 同一时间只有一个供应商处于启用状态；切换后立即生效，不需要重启服务。
- 用量面板：按用途（推荐 / 新菜生成 / 问答 / Embedding）统计近 7 天的调用次数、失败率、平均耗时和 token 用量。

## 3. 菜谱管理

- **列表**：按名称搜索，按状态（已发布 / 待审核 / 已驳回 / 已下架）、来源（种子导入 / 模型生成 / 手工录入）、菜系、餐次筛选。
- **编辑**：基本信息、食材（从食材库选择，或新建食材）、步骤、标签；保存前做校验，例如用量单位合法、至少有一个步骤。
- **审核队列**：模型生成的新菜按时间排列，显示由哪位用户的推荐触发、用的什么模型。可以编辑后发布，也可以驳回并填写原因。
- **食材库**：维护标准名、别名、品类、过敏原标签，以及「常备调料」标记（采购清单默认不列入常备调料）。
- **种子导入**：查看导入批次和失败条目，可以重新导入单条。

## 4. 用户与邀请

- 生成邀请码：可设有效期（默认 7 天）和可用次数（默认 1 次）；可撤销。
- 用户列表：昵称、注册时间、最近活跃时间；可以撤销某台设备的令牌。

## 5. 不在首版范围

- 多管理员权限细分、操作审计界面（操作日志先只写服务端日志）。
- 生鲜平台跳转模板管理（随「采购清单」里程碑一起做）。
